# Проверяемое качество retrieval

## Регрессии на реальном snapshot

19 октября 2026 проверены 45 авторских публичных запросов: по 15 RU/KK/EN,
28 с названием, 11 с категорией и 6 намеренно пустых. Это примеры разработки,
а не пользовательские логи и не независимая человеческая разметка. Relevant IDs
в `tests/fixtures/real-snapshot-cases.json` заданы по source names/categories;
category judgments дополнительно проверяются относительно всего разрешённого
snapshot, radius и известных static required. Имена, категории и удобства
источника не равны независимой проверке заведения.

Общая конфигурация обеих реализаций: **628 одинаковых мест**, SHA-256 файла
`bc919999881d216cf7692d2c7e3b0289fc388ce227c94a8fd00f0966bd2030df`,
origin 51.127/71.43, radius 30000 м, pool 1000, k=3. Только retrieval-модуль
различается: baseline d10236a (lexicon v1) против v2. Исходные judgments не
построены из вывода алгоритма; они содержат известные дефекты, поэтому рост
числа пройденных случаев является результатом исправлений, а не доказательством
качества на будущих запросах.

Только 3 запроса содержат required constraints; unknown required здесь ещё
передаются recommender, а не считаются выполненными. Сквозные API-тесты отдельно
проверяют обязательные Wi-Fi/туалет по Estet Coffee, unknown Wi-Fi у Drinkit,
неизвестные розетки/тишину, отсутствие скрытого ослабления и отсутствие внешних
вызовов. Набор не измеряет актуальность расписаний или близость к ориентиру.

Машиночитаемые результаты: [baseline](real-baseline.json),
[новая реализация](real-improved.json). В них сохранены реальные задержки каждого
запроса. Прогоны выполнялись на Windows параллельно с другими проверками:
медиана 1654/1779 мс, p95 3883/4659 мс для v1/v2. Это одиночные прогоны, а не
latency benchmark; ускорение не заявляется. JSON Schema проверяет каждый Place
на границе модуля, в том числе все source facts.

```powershell
uv sync --locked --all-packages
.venv/Scripts/python.exe -X utf8 packages/retrieval/evaluate_real.py --snapshot data/samples/astana-osm.json
```

Для сравнения другой реализации запускайте тот же evaluator с её `retrieval/src`
первым на PYTHONPATH. Пакет city_data и snapshot должны оставаться одинаковыми.
Hash mismatch останавливает оценку: rebind допустим после проверки source IDs и
категорий, а не после автоматического пересоздания judgments из новых результатов.

## Synthetic-набор

`packages/retrieval/evaluate.py`: 10 synthetic POI и 27 авторских запросов, в том
числе 24 положительных и 3 no-match. После исправлений все 27 проходят, средний
Recall@3 и MRR@3 положительных запросов равен 1. Два прежних промаха «Somewhere to
study» и «Дәмді ас» стали регрессионными случаями. Расширение словаря по ним не
является независимой оценкой. Это проверка контролируемой реализации.

Unit-тесты проверяют radius, score→distance→ID, ограничения pool/candidate_limit,
JSON equality, неизвестные/противоречивые/dynamic required, aliases, literal names,
однозначные/неоднозначные опечатки, отрицания, ориентиры, cancellation, timeout и
отсутствие выдуманных evidence. Корпус мал; процент качества города не заявляется.

## Локальная multilingual модель

Выполнен отдельный CPU-эксперимент с pinned `intfloat/multilingual-e5-small`,
официальным FP32 ONNX, query/passage prefixes, mask-aware mean pooling и L2
normalization. Скрипты, точные зависимости, SHA модели и результаты:
[evals/local-semantic](../../evals/local-semantic/README.md).

На 16 авторских запросах dense-only поиск иногда находит полезные категории,
но путает отрицание и намеренно нерелевантные запросы; score не даёт безопасного
универсального порога no-match. В этом эксперименте не применялись radius,
required и reranking: это не сравнение готового hybrid retrieval с продуктом.
Модель не включена в runtime по умолчанию. Сначала нужен независимый отложенный
набор и сравнение lexical против hybrid с прежними проверками фактов. Малый
корпус допускает точный поиск; отдельная ANN/vector DB сейчас не обоснована.

## Оставшаяся оценка

Нужны отдельно размеченные жителями запросы на RU/KK/EN с редкими названиями,
смешанными языками, неоднозначностями и no-match; оценка полезности 1–3 вариантов,
полноты источников и актуальности удобств. Сырые запросы и координаты не собирать
без отдельно согласованного процесса. Текущие авторские regression tests нельзя
переименовывать в независимый тест после дальнейшей настройки по ним.
