# Python API на Render для оценки проекта

Профиль рассчитан на небольшую публичную демонстрацию: сайт работает в Cloudflare,
Python API — на Render, ИИ — через OpenAI. Это конфигурация для запуска, а не отчёт
об уже выполненном деплое. GitHub Actions собирает образ на Linux и проверяет
его с 512 МБ памяти, непривилегированным пользователем, закрытой сетью и реальным
каталогом. CI проверяет настройки Blueprint без внешнего ИИ и секретов. Отдельно
выбранные в Render настройки TomTom требуют своего live-QA после публикации.

`render.yaml` создаёт один Docker web service с `plan: free`, одним экземпляром,
ручными обновлениями и проверкой `/v1/health/ready`. Ветка берётся из выбранного
Blueprint; `main` не навязывается. Эти поля сверены 19 октября 2026 года с
[актуальной спецификацией Render](https://render.com/docs/blueprint-spec).

## Что входит в образ

`infra/render/Dockerfile` устанавливает Python workspace из `uv.lock` и включает
только проверенный публичный снимок `data/samples/astana-osm.json`: **682 реальных
мест**. SHA-256 файла:

```text
35e2ac72f0a10b00870ed323f4d8f313c9933c67b5115de5803e5e517211fdc2
```

Сборка проверяет хеш и загрузку всех 682 объектов. Исходные даты и атрибуция OSM /
Wikidata сохраняются. Для 11 мест добавлены 80 описаний и утверждений из 16
[проверенных официальных страниц](../data/official-sources.md); неподтверждённые
удобства не объявляются доступными. Снимок содержит исходные данные OSM на
`2026-10-20T14:44:50Z`, включая 54 записи с явным `shop=mall`;
время деплоя не является полевой проверкой каждого факта. После семи дней
API продолжает показывать каталог с признаком `stale`. Для обновления нужен новый
проверенный импорт, соответствующий хеш в Dockerfile и новый деплой.

Поиск — существующий локальный BM25 без загрузки embedding-моделей. Процесс
работает от непривилегированного пользователя; JSON доступен только для чтения.
Обычный `infra/Dockerfile` сохраняет прежний fixture-режим и не меняется.

## Первое развёртывание

1. В Render создать Blueprint из репозитория и выбрать ветку с этой конфигурацией.
   Перед созданием проверить, что показан **Free** и ровно один web service.
2. Ввести три переменные, отмеченные `sync: false`:

   | Переменная | Значение |
   | --- | --- |
   | `OPENAI_API_KEY` | Ключ выделенного OpenAI API-проекта, только в Render |
   | `LLM_MODEL` | ID доступной этому проекту модели с Responses API и JSON Schema output |
   | `CORS_ORIGINS` | Точный HTTPS origin сайта Cloudflare без пути и конечного `/` |

   Модель намеренно не зафиксирована: её доступность проверяется для конкретного
   ключа. Текущие лимиты ответа — 512 токенов для объяснения и 1536 для разбора
   запроса; модель, расходующая весь лимит на рассуждение, может переходить в fallback.
   По выбору владельца используется `LLM_MODEL=gpt-6-luna`. Модель поддерживает
   Responses API и Structured Outputs. Для короткого разбора пожелания и объяснения
   маршрута приложение явно задаёт `reasoning.effort=none`, сохраняя лимиты ответа
   и строгую JSON Schema. Доступ конкретного API-проекта проверяется живым запросом.
   [Официальная карточка модели](https://developers.openai.com/api/docs/models/gpt-6-luna).
3. Выполнить первый деплой. Для последующих обновлений использовать Manual Deploy;
   автоматические деплои выключены. Render запрашивает `sync: false` только при
   первом создании Blueprint; новые/изменённые секреты существующего сервиса
   задаются через Environment. [Правила секретов Blueprint](https://render.com/docs/blueprint-spec#prompting-for-secret-values).
4. После получения адреса API задать **на серверной стороне Cloudflare**
   `ASTANA_API_URL=https://<имя-сервиса>.onrender.com`,
   `ASTANA_ALLOW_FIXTURES=false`, `ASTANA_MAP_PROVIDER=openfreemap`.
   Префикс `/v1` в `ASTANA_API_URL` добавлять не нужно. Ключ OpenAI в Cloudflare
   или `NEXT_PUBLIC_*` не копировать.

## Подготовленный профиль TomTom

Для текущей оценки выбран OpenAI `gpt-6-luna` и TomTom. Базовый `render.yaml`
содержит keyless `osrm_public`/`nominatim`; существующий сервис можно переключить
через Environment после интеграции TomTom adapters:

| Переменная | Значение |
| --- | --- |
| `LLM_PROVIDER` | `openai` |
| `LLM_MODEL` | `gpt-6-luna` |
| `TOMTOM_API_KEY` | Ключ только в защищённых настройках Render |
| `ROUTING_PROVIDER` | `tomtom` |
| `ASTANA_MAP_LOOKUP_ENABLED` | `true` |
| `ASTANA_MAP_LOOKUP_PROVIDER` | `tomtom_osm` |
| `ASTANA_CONTEXT_TIMEOUT_SECONDS` | `10` (TomTom-цепочка отдельно ограничена 6,5 с) |
| `ASTANA_CONTEXT_RETRIES` | `0` |
| `ASTANA_ROUTE_ALLOW_APPROXIMATE` | `true` |

Ключу нужен доступ к используемым продуктам Places, Routing и Traffic. Значение
ключа не переносится в GitHub, Cloudflare frontend или `NEXT_PUBLIC_*`. Сохранение
через Save only не запускает новую версию: после успешного CI выполнить Manual
Deploy выбранного commit. Эти настройки подготовлены; успешный live-доступ к
TomTom и новой конфигурации модели фиксируется только после отдельной проверки.

Render передаёт env и на сборку Docker в виде build arguments. Этот Dockerfile не
объявляет ARG для ключей и не читает их при сборке. Дополнительные secret files
для этого профиля не нужны. [Docker и секреты Render](https://render.com/docs/docker#environment-variable-translation).

## Провайдеры и ограничения

| Функция | Настройка профиля | Поведение |
| --- | --- | --- |
| ИИ | `LLM_PROVIDER=openai` | Общий лимит intent + explanations: 10 обращений/мин, 100 за скользящие 24 ч |
| Карточка по клику | Подготовлен `tomtom_osm` | Отдельные OSM и nearby TomTom POI; TomTom до 8 мест/250 м, 6 попыток/мин, 100/сутки, интервал 5 с, без кэша |
| Пеший маршрут | Подготовлен `tomtom` | Pedestrian v1 → OSRM foot; единый deadline ≤6,5 с; TomTom 10 попыток/мин, 600/сутки, без кэша и retries |
| Пробки | Серверный `TOMTOM_API_KEY` | Отдельные дорожные samples по действию пользователя; до 12 запросов/мин, кэш 60 с; 3D-модели остаются симуляцией |
| Погода | `ASTANA_WEATHER_ENABLED=false` | Погодные выводы отключены |

Публичные Nominatim/FOSSGIS подходят здесь только для малой оценки; кэш и лимиты
не заменяют условия провайдеров. При росте использования нужен собственный или
договорной сервис. Сбой маршрутного API даёт явно обозначенную приблизительную
оценку без выдуманной геометрии. Кэшированные данные не получают новую дату
источника. Подробнее — [провайдеры карты](map-services.md).

Ограничение ИИ считает попытки, включая неудачные. Установка любого из
`ASTANA_LLM_REQUESTS_PER_MINUTE` / `ASTANA_LLM_REQUESTS_PER_DAY` в `0` прекращает
новые внешние вызовы; поиск и локальный разбор продолжают работать. Это ограничение
числа запросов, **не денежный потолок**. Стоимость OpenAI оплачивается отдельно и
зависит от выбранной модели. Счётчики живут в памяти и сбрасываются при рестарте:
повторный холодный старт Free также сбрасывает квоту. Для устойчивого суточного
ограничения нужен внешний постоянный счётчик/шлюз и контроль расходов провайдера.
`CORS_ORIGINS` ограничивает браузерный доступ, но не является авторизацией API.

Один worker и один экземпляр обязательны для нынешних квот и социальных сессий.
Гостевые комнаты, события и серверные кэши хранятся в памяти и теряются после
перезапуска. Постоянной базы пользователей этот профиль не создаёт.

## Проверка после запуска

Проверить `/v1/health/ready`: нужен HTTP 200. Этот endpoint проверяет готовность
локального каталога, но не оплачиваемый вызов OpenAI. HTTP-проверка Render
настроена именно на него. [Health checks Render](https://render.com/docs/health-checks).

Если процесс запущен, но readiness остаётся 503, проверьте startup log:
`Service initialization failed: stage=<этап> exception=<класс>`. Он содержит
только фиксированный этап и класс ошибки, без текста исключения, ключей и
параметров запроса. Проверьте соответствующие несекретные настройки в Environment.
Не заменяйте readiness на `/v1/health/live`: живой процесс может не загрузить каталог.

Затем открыть `/v1/data-status`: `total_places` должен быть **682**, заголовок
`X-Astana-Data-Mode` — `live`, даты источников — сохранённые даты снимка.
Во фронтенде проверить поиск Estet Coffee, карточку здания по клику, применение
запроса, настоящий пеший маршрут и нумерованные остановки. При проверке ИИ
убедиться, что ответ помечен `openai`, а не локальным fallback; ключ и запрос не
вставлять в логи и отчёты. Успех readiness сам по себе не доказывает работу ИИ.

Для нового профиля отдельно проверить TomTom Places по клику, `provider` пешего
маршрута и Traffic. Успешный OSRM fallback не записывать как успех TomTom; результаты
карточек OSM и TomTom должны сохранять разные ID и источники. Проверить пожелания
«Прогулка по паркам», «Прогулка по набережной», «Посмотреть архитектуру» и смешанную
прогулку: обычные preferred-удобства не должны вытеснять цель запроса, а явно
required-условие с неизвестным значением по-прежнему исключает место. Не обещать
три результата, если подтверждены только два. SHA и фактический результат записать
в [публичный QA](../ux/public-deployment-qa.md) до обновления материалов защиты.

Free засыпает после 15 минут без входящих запросов; пробуждение может занимать
около минуты. Первый запрос через фронтенд поэтому может завершиться таймаутом:
открыть readiness, дождаться ответа и повторить действие. Free имеет общий лимит
750 часов/месяц на workspace; bandwidth/build minutes учитываются отдельно.
Диск эфемерный, и Render не рекомендует Free для production. Перед запуском
проверить текущие квоты и условия оплаты в аккаунте. [Ограничения Free](https://render.com/docs/free).

## Локальная сборка при наличии Docker

```sh
docker build -f infra/render/Dockerfile -t astana-api-evaluation .
docker run --rm -p 10000:10000 -e LLM_PROVIDER=none astana-api-evaluation
```

Этот запуск проверяет реальный каталог с локальными объяснениями и без ключа.
Для включения внешних провайдеров настройки передаются отдельно во время запуска.
Не передавать реальные секреты через `--build-arg` и не коммитить `.env`.
