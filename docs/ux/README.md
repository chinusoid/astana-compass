# Интерфейс Astana Compass

Текущий интерфейс строится вокруг карты Астаны и постоянной навигации. На desktop
слева расположены узкая панель разделов и прокручиваемая панель шириной около
400px, справа — карта. На мобильном карта занимает экран, а поиск и план доступны
в выдвижной нижней шторке; после поиска маршрут показывается на карте.
Разделы доступны в нижней навигации. Большого рекламного блока нет.

Разделы: `/` — каталог и старт на карте, `/walk` — условия и план прогулки,
`/saved` — избранное, `/about` — источники и приватность, `/party` — совместная
прогулка, `/events` — непроверенные события сообщества. План хранится в памяти вкладки при переходах между разделами;
избранное — локально, с удалением. Ручные координаты остаются запасным способом
выбора старта внутри раскрываемого блока. Геолокация запрашивается только действием.

Визуальные ориентиры — белые поверхности, зелёные действия, компактные карточки,
видимый фокус, отдельные статусы неизвестных фактов и приблизительных расчётов.
Причина рекомендации показывается сразу; подробные проверки ограничений и
источники доступны дополнительно. Данные не обрезаются ради размеров карточки.

Сценарии для демонстрации и условия их проверки — в [DEMO.md](../DEMO.md).
[judging-demo.md](judging-demo.md) сохраняет более ранний план показа и границы
обещаний; исторические результаты не подтверждают новый интерфейс автоматически.
Текущая реализация и ограничения описаны в [ARCHITECTURE.md](../../ARCHITECTURE.md).

Сетевой слой карты, POI, расписания, пешеходный маршрут и генерация объяснений —
разные источники. Реальная подложка не превращает synthetic POI в реальные.
Объёмные здания не подтверждают доступность входа или точную высоту.
«Демо движения» машин/людей — явно подписанная симуляция. Отдельная кнопка
«Реальные пробки» требует серверного ключа TomTom и показывает ограниченную
выборку потоков; движущиеся точки даже в этом режиме обозначают условную плотность,
а не реальное количество автомобилей. Без ключа реальные данные не заявляются.

Новая компоновка и расширения должны пройти проверки текущего checkout:
typecheck, lint, unit, build и сценарии CI/CUA. Этот документ не является отчётом
об успешном прохождении ещё не выполненных проверок.
