# Team 03 · UX, доступность и границы данных

## Пользовательский путь

Визуальный язык: спокойный светлый фон, тёмно-зелёные действия, оранжевые
ориентиры, крупный редакционный заголовок. Desktop объединяет форму и план слева,
карту и варианты справа. На узком экране порядок: форма → карта → варианты →
каталог → выбранный план. Все сведения доступны без WebGL и без геолокации.

1. Выбрать RU / ҚАЗ / EN; язык DOM тоже меняется.
2. Ввести пожелание и явно выбрать важные условия. Пресеты задают видимое
   preferred-условие, а не скрытое required из текста.
3. Ввести старт вручную, отметить карту или явно запросить геолокацию.
4. Указать минуты, начало по времени Астаны и возвращение.
5. Сравнить самостоятельные варианты, открыть «Почему подходит» и источники.
6. Добавить до трёх остановок; порядок меняется кнопками. Рассчитать всю поездку.
7. При no_match сохранить выбор, изменить условия самому и повторить расчёт.

## Матрица состояний

| Состояние | Интерфейс |
| --- | --- |
| До запроса | Объяснение следующего действия, доступный каталог |
| Loading | Локальный индикатор и aria-busy; повторный запрос ограничен |
| Empty catalog | Отдельное пустое состояние каталога, без фиктивных карточек |
| Matched | Подтверждённые required; отдельные альтернативы |
| Partial | Заметное ограничение и сохранённые предупреждения |
| No match | Причина, самостоятельное изменение условий, пустые результаты |
| Needs clarification | Вопрос и новый валидный query без несуществующих полей памяти |
| Provider error / timeout | Локализованная ошибка, сохранённая форма, повтор |
| Rate limit | Предложение подождать; без автоматической петли повторов |
| Invalid response | Не показывать непроверенные факты и усечённый маршрут |
| Geolocation denied | Ручной старт остаётся доступным |
| Map failure | Список и форма сохраняют все действия |
| AI refusal/malformed/unavailable | Данные и доказательства остаются; показан fallback |
| Fixture | Явное включение и постоянная маркировка synthetic |

## Доступность и приватность

Нативные input/select/checkbox/details, видимый focus, skip-link, нативный modal
dialog с Escape и восстановлением фокуса. Кнопки имеют зону не менее 44px, включая
карту и перестановку остановок. Поддержан reduced motion. Цвет не единственный
носитель статуса. Текст не обрезается ради красивой карточки. Источники
открываются как http(s)-ссылки; javascript и URL с credentials не становятся ссылками.

Избранное хранит только ID/название/синтетическую метку, без координат и query.
Факты запрашиваются заново при открытии. Доступны удаление одного и всего списка.
Feedback отправляется только по нажатию и содержит request_id/rating/comment=null.
Карта загружается по действию пользователя; показано, что tile-сервис получает
IP и видимую область. Геолокация не запрашивается при загрузке страницы.

## Карта и условия провайдера

MapLibre GL JS 6.15.0 — renderer. Встроенный вариант подложки — Standard raster
tiles OpenStreetMap, а не источник рекомендаций и не маршрутизатор.

Проверены 19.10.2026:

- [OSMF Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/):
  корректный HTTPS endpoint, видимая attribution, обычный browser Referer,
  уважение cache headers; никаких bulk/offline/prefetch загрузок. Сервис best effort,
  без SLA и обещаний безлимитности.
- [OSM copyright](https://www.openstreetmap.org/copyright): атрибуция остаётся
  внутри карты, также доступна ссылка сообщения об ошибке.
- [MapLibre v6 migration](https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/):
  отдельный module worker и shared module размещаются на собственном origin.
- [MapLibre raster example](https://maplibre.org/maplibre-gl-js/docs/examples/map-tiles/):
  используется raster source; поставщик выбирается независимо от renderer.

Настройка `ASTANA_MAP_PROVIDER=none` полностью отключает внешние тайлы. Перед
публичным масштабированием координатор выбирает провайдера с подходящими лимитами,
атрибуцией и условиями. В этом PR нет paid account, нового hosting или публикации.

## Что остаётся внешним

Точность реальных POI, маршрутизация, расписания, качество поиска и inference
зависят от API и интеграции команд 01/02. Погодного DTO пока нет. Новые свойства
не добавляются в shared schema из frontend. Переводы интерфейса покрывают ru/kk/en;
имена и тексты из источников сохраняются как получены, без выдуманных переводов.
