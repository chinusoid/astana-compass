# Проверка интерфейса на реальных источниках

Карточка показывает отдельно **описание источника** и **краткую сводку по известным фактам**. Адрес, расписание, кухня, места для сидения, Wi-Fi и туалет попадают в сводку только из `known`-фактов со ссылкой на существующее evidence. Категория кафе не подтверждает Wi-Fi, розетки или помещение. Отрицательные исходные значения остаются отрицательными, неизвестные — неизвестными.

Описание выбирается из OSM/Wikidata на выбранном языке, если такой исходный текст существует; иначе сохраняется исходное `Place.description`. Приложение не придумывает перевод или описание из названия категории. Подпись и ссылка ведут к evidence выбранного текста. Субъективный текст источника остаётся утверждением источника, а не собственной оценкой приложения.

В деталях названия полей и распространённые значения локализованы на RU/KK/EN. Исходные значения, заметки и provenance сохранены в раскрываемых блоках. Расписание отображается без вычисления «открыто сейчас»; отметки дней недели переведены только для чтения. Доступность в выбранное время определяется отдельной проверкой контекста.

Поиск каталога ищет название; для пожеланий и required/preferred предназначена страница прогулки. Изменённый, но ещё не отправленный запрос явно отмечен. Пустой поиск предлагает другое написание и сброс. `no_match` не утверждает, что подходящих мест нет в городе: он сохраняет обязательные условия и открывает пояснения ответа.

## Сценарии реального browser QA

`tests/e2e/live.spec.ts` обращается к настоящему API, без подмен HTTP-ответов. Нужен обогащённый snapshot с указанными source ID:

| Сценарий | Проверка |
| --- | --- |
| Estet Coffee, `osm:way/1395465867` | В мобильном RU/KK/EN видны исходные Wi-Fi, туалет, расписание 24/7; это не заявление о работе сейчас. Источники и ODbL доступны. |
| Drinkit, `osm:node/11783576043` | `internet_access=yes` не выдаётся за Wi-Fi: `has_wifi` остаётся unknown, положительная Wi-Fi-сводка отсутствует. |
| Жетісу саябағы, `osm:way/69232075` | Английское описание Wikidata сохраняется при отсутствии русского перевода; ссылка совпадает с exact revision evidence. |
| Неизвестное название | Сообщение относится к текущему каталогу; сброс возвращает список. |
| Поиск от Estet Coffee с обязательным Wi-Fi | Выданные рекомендации подтверждают `has_wifi` источниками. Добавление обязательных розеток даёт `no_match`, условие не ослабляется. |

## Запуск

Для уже работающего разрешённого live-приложения:

```powershell
$env:ASTANA_LIVE_WEB_URL = 'http://127.0.0.1:43105'
pnpm --dir apps/web test:live
```

Для отдельного автоматического локального прогона после locked installation, установки Chromium и production build:

```powershell
uv sync --locked --all-packages
pnpm --dir apps/web install --frozen-lockfile
pnpm --dir apps/web exec playwright install chromium
pnpm --dir apps/web build
pnpm --dir apps/web test:live:local
```

Команда `test:live:local` включает `ASTANA_LIVE_LOCAL=true` в конфигурации Playwright. Playwright запускает и завершает собственные процессы: API на `127.0.0.1:18082`, web на `127.0.0.1:43105`; `reuseExistingServer=false` исключает присоединение к уже занятому адресу. Путь snapshot абсолютный и относится к этому checkout. Режим — live, объяснения — локальные, внешние модели/маршрутизация/погода/карта отключены; ключи внешних провайдеров для API обнулены. Сетевого импорта при запуске нет. Не запускайте build одновременно с тестовым webServer в одном checkout.

Без `ASTANA_LIVE_WEB_URL` и без local-флага внешний live-набор пропускается. Ошибка запуска или занятый порт не означает успешный тест. Скриншоты реальных карточек, описания и `no_match` сохраняются в `apps/web/test-results/live/`; failure trace также сохраняется. Результат конкретного запуска, commit и осмотр скриншотов записываются в итоговый отчёт. Само наличие этих сценариев не подтверждает их прохождение, live inference или качество всех городских рекомендаций.
