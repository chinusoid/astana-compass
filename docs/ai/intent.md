# Разбор запроса перед подбором мест

`astana_ai_providers.intents.create_intent_analyzer()` создаёт локальный или hosted-анализатор. Он извлекает пожелания пользователя; в «Прогулке» запускается автоматически при поиске. Он не проверяет свойства заведений и не заменяет RAG, источники фактов, маршрутный движок или final required checks.

```python
from astana_ai_providers.intents import create_intent_analyzer

async with create_intent_analyzer(
    provider="rules",  # либо openai/nvidia с серверной конфигурацией
    model=None,
    api_key=None,
    timeout_seconds=6,
) as analyzer:
    proposal = await analyzer.analyze(
        "Хочу тихое кафе с розеткой у MEGA на 45 минут", "ru"
    )
```

Публичный ответ валидируется по каноническому `IntentResponse`. Координатор подключает его к `POST /v1/intent`. У анализатора есть `analyze(query, locale)` и `aclose()`; тестовый HTTP transport передаётся именованным параметром `transport`. Секрет берётся только из серверной конфигурации, модель явно выбирается оператором. Пакет не выбирает платную модель и не выполняет запрос при создании.

## Что понимает текущая версия

| Сценарий | Предложение и границы |
|---|---|
| «У MEGA есть 30–60 минут» | Точный текст ориентира, 1800 секунд как нижняя граница диапазона, предупреждение и подтверждение точки на карте. Координаты не угадываются. |
| «Тихое кафе с розеткой» | Категория cafe, quiet и has_power_outlets с точными цитатами. Это желания пользователя, а не подтверждение удобств кафе. |
| «С ребёнком» | child_friendly и вопрос о возрасте/коляске. Доступность с коляской или наличие площадки не выводятся автоматически. |
| «Турист, до вылета два часа» | Время прогулки остаётся null. Уточняется остаток после дороги в аэропорт, регистрации и контроля. Весь запас до вылета не предлагается тратить на маршрут. |
| «Ночная активность» | Категория nightlife при прямом упоминании и уточнение даты/формата. Нет обещания открытого заведения, безопасности или существующего мероприятия. |

Поддерживаются RU/KK/EN, распространённые названия категорий, числовые и некоторые словесные минуты/часы. Поддержанные ограничения совпадают с UI: indoor, wheelchair_accessible, child_friendly, free_entry, open_at_requested_time, quiet, has_power_outlets, has_wifi, toilets. Wi-Fi предлагается только по явным Wi-Fi/вайфай/wireless формулировкам; слово «интернет» само по себе не определяет тип подключения. Все ограничения возвращаются как `value: true, strength: preferred`. Превращение предложения в обязательное условие требует явного действия пользователя; существующие required условия этот этап не ослабляет.

«Розетка не нужна», «socket is not required» и «керек емес» исключают условие, а не требуют отсутствия розеток. Противоречащие друг другу упоминания не применяются. Сложная или неподдержанная формулировка может потребовать ручного уточнения: это ограниченный извлекатель, а не обещание полного понимания любого языка. Составные и неоднозначные длительности остаются null; время вне 60–14400 секунд не обрезается скрытно.

## Hosted-ответ и проверка

OpenAI использует Responses API с `store: false`, strict JSON Schema и ограничением вывода. NVIDIA использует официальный hosted Chat Completions endpoint, системное JSON-описание и строгую локальную проверку: поддержка constrained decoding различается по моделям, поэтому `guided_json` из self-hosted NIM не отправляется и универсальная поддержка `response_format` не предполагается.

Внутренний формат ответа провайдера — узкий протокол извлечения, не новый публичный DTO. Он содержит категории и поддержанные ключи с цитатами, время, текстовый ориентир и коды уточнений. Произвольный текст модели не показывается как объяснение: вопросы и предупреждения формируются локально на выбранном языке.

Проверка отвергает лишние поля, дубли ключей JSON, неизвестные значения, повторные условия, несовпадающие цитаты и числа, попытки вырезать отрицание из контекста, tool calls, отказ или незавершённый вывод. Для признака нужна распознаваемая лексика внутри цитаты и положительный контекст исходного запроса. Время вычисляется правилами и должно точно совпасть с моделью; дедлайн рейса остаётся null даже при ответе модели с числом. Указание ориентира допускается лишь точной подстрокой запроса, без геокодирования.

Повторно используется общий HTTP transport адаптера объяснений: фиксированный официальный endpoint, отсутствие redirects/proxy-env, общий timeout, 64 KiB на ответ, identity encoding и запрет декомпрессии до чтения. Ошибка/таймаут/невалидный ответ приводит к `provider: rules` и явному предупреждению. Ошибка запроса пользователя не маскируется под успешный разбор. Отмена coroutine сохраняется. Ни ключ, ни тело ошибки провайдера не возвращаются пользователю.

## Приватность

В режиме rules сетевых запросов, хранения и журналирования нет. При явно включённом hosted-разборе передаются текст запроса, язык и предложения локальных правил. Координаты карты, party locations, история диалога, профиль и ключ в JSON не добавляются. В отличие от генератора объяснений, которому не нужен сырой запрос, для понимания намерения текст отправляется выбранному провайдеру; UI должен сообщать об этом до использования. Если пользователь сам написал личные сведения в запросе, они входят в отправленный текст. `store: false` — настройка Responses API, а не обещание отсутствия любой обработки или хранения со стороны провайдера.

Без настроенных модели/ключа используется rules с прямым указанием, что языковая модель не применялась. Никакого платного вызова для локальных тестов не требуется.

## Проверки

`pytest packages/ai_providers/tests/test_intents.py` проверяет пять сценариев на трёх языках, отрицания, конфликты, единицы, диапазоны/границы, точные цитаты, обрезанное моделью отрицание, 401/429/500, timeout, malformed/oversized/encoded ответы, tool calls, отмену и отсутствие секретов в ответе. HTTP выполняется только через MockTransport. Общий набор `test_generators.py` дополнительно проверяет транспорт и формат ответов провайдеров.

Источники реализации: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [официальный NVIDIA hosted Chat Completions API](https://docs.api.nvidia.com/nim/reference/qwen-qwen3-5-122b-a10b-infer), [NVIDIA NIM Structured Generation](https://docs.nvidia.com/nim/large-language-models/1.15.0/structured-generation.html). Страница конкретной модели NVIDIA использована для формы hosted API; она не выбирает модель для продукта и не доказывает доступность всех параметров у других моделей.


## Применение в интерфейсе прогулки

По запросу владельца поиск сам вызывает `/v1/intent`: поддержанная длительность из текста имеет приоритет над дополнительным полем времени, а извлечённые удобства добавляются только как `preferred`. Канонические `source_quote` и `time_evidence` проверяются до применения. Включённые вручную `required` остаются обязательными; координаты не берутся из текста. Распознанные настройки показаны отдельной подписью и не превращаются в отмеченные ручные фильтры. При изменении порядка или удалении остановки извлечённая длительность сохраняется для того же текста и языка.

Жёлтая кнопка «Фильтры» раскрывает дополнительные настройки. По умолчанию нет заданной длительности, возврата к началу и требований к удобствам. Отсутствие времени представлено внутренним конвертом 86400 секунд, поскольку текущий HTTP-контракт требует конечное число. Этот предел не показывается как выбранные пользователем 24 часа. Маршруты длиннее указанного ориентира по-прежнему доступны с предупреждением о превышении.

Разбор по отдельной кнопке и ручное подтверждение сохранены внутри дополнительных настроек для проверки результата. Неоднозначная, составная или неподдержанная длительность не угадывается. Если endpoint разбора не отвечает за 9 секунд, поиск продолжает использовать исходный текст и явно сообщает о недоступности отдельного извлечения условий. Сам спутник даёт локальные контекстные подсказки и не выдаётся за отдельный разговор с моделью.
