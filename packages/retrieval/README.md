# Astana retrieval

Рабочий локальный `Retriever` для нормализованного snapshot: категории и небольшой словарь RU/KK/EN, взвешенный BM25 и детерминированный выбор кандидатов. Используется публичный `PlaceRepository`; файл данных и импорт принадлежат `astana_city_data`. Сетевых запросов, ключей, LLM, embeddings или отдельной vector DB в этом пакете нет.

```python
from astana_retrieval import create_retriever

retriever = create_retriever(repository=repository, config={"mode": "live", "timezone": "Asia/Almaty"})
result = await retriever.retrieve({
    "query": "Тихое кафе с розеткой", "locale": "ru",
    "origin": {"lat": 51.1, "lon": 71.4}, "radius_meters": 5000,
    "candidate_limit": 12, "constraints": [],
})
await retriever.aclose()
```

Вход и выход проходят канонические `RetrievalRequest`/`RetrievalResponse`. Factory не выполняет I/O. Repository заимствован: `aclose` retriever не закрывает его. В API он закрывается владельцем composition.

## Ранжирование и границы

1. Один вызов `repository.nearby` получает максимум `ASTANA_RETRIEVAL_POOL_LIMIT` ближайших POI (по умолчанию 500, допустимо 100–1000). Полная выборка этого размера сопровождается предупреждением о возможном пропуске релевантных мест дальше по расстоянию. На один вызов установлен timeout.
2. Повторно проверяются `Place`, уникальность IDs и сферический радиус по haversine с радиусом Земли 6 371 008,8 м. Это географический фильтр; он не является пешим маршрутом. Попадание в radius не заменяет построение маршрута.
3. Подтверждённое нарушение static required исключает место. Сравнение — точное JSON-равенство: `true` отличается от `1`, включая массивы. Unknown/conflicting required и `open_at_requested_time`/`weather_suitable` сохраняются для последующих проверок при наличии поисковой релевантности; динамическое значение из snapshot никогда не считается текущим.
4. Небольшой версионированный словарь распознаёт категории, распространённые формы слов и удобства на RU/KK/EN. Это ручные поисковые расширения, не обученная multilingual модель. Отрицательные категории исключаются; отрицательные/необязательные удобства не становятся положительными сигналами. Сложная грамматика, произвольные опечатки и все формы казахского языка не покрыты.
5. Индексируются исходные name, description, категории и известные факты. `name:ru`, `name:kk`, `name:en` используются лишь при наличии known факта из источника. Переводы не создаются. Имена/категории имеют вес 3, описание — 1, known true удобства — 2. Вхождения нормализованы до присутствия терма в каждом поле, чтобы повторение рекламного текста не усиливало результат неограниченно. BM25 использует `k1=1.2, b=0.75`; IDF вычисляется по ограниченному корпусу после фильтров.
6. Совпавшие подтверждённые условия/удобства дают прибавку 0,2. География определяет порядок при равном score; окончательное равенство разрешает ID. При отсутствии текстового сигнала и подтверждённых явно заданных условий возвращается пустой результат. Случайное ближайшее место не подставляется. Вход с неизвестным названием не считается подходящим только за счёт побочного условия вроде `indoor`.

`matched_fact_keys` включает только реально присутствующие known факты, совпавшие с запросом или explicit constraint. Слова «тихо» в описании могут влиять на текстовый score, но не создают `quiet` fact/evidence. Извлечённые из текста пожелания не превращаются в hard filters; окончательные required проверки выполняет recommender после context enrichment.

Каждый hit имеет `score_kind="lexical"`; `strategy="snapshot-bm25-ru-kk-en-1"`. Warnings на языке запроса прямо сообщают отсутствие semantic embeddings. Score — относительный сигнал, не вероятность и не сравнимая между разными запросами оценка качества.

## Настройка

| Серверная переменная | По умолчанию | Допустимо |
|---|---:|---|
| `ASTANA_RETRIEVAL_POOL_LIMIT` | 500 | целое 100–1000 |
| `ASTANA_RETRIEVAL_TIMEOUT_SECONDS` | 5 | конечное число больше 0 и не больше 30 |

Запрос ограничен 2000 символами, 20 constraints и canonical candidate_limit 1–100. Индексируются не более 500 символов каждого имени и 8000 символов описания. Неправильная конфигурация, сломанные repository payloads и превышенный pool отклоняются; исключения не включают сырой запрос. Cancellation сохраняется. Пользовательские координаты, запросы и результаты не записываются в логи/кэш. Нет скрытого сетевого fallback или платного вызова.

## Проверки

До регистрации workspace координатором можно запускать из корня PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'packages/retrieval/src')
.venv/Scripts/python.exe -m pytest packages/retrieval/tests
.venv/Scripts/python.exe -m ruff check packages/retrieval
.venv/Scripts/python.exe packages/retrieval/evaluate.py
```

Последняя команда явно работает с независимым синтетическим корпусом и ручными judgments. Она не измеряет качество реальных заведений. Подробнее: [качество и ограничения](../../docs/retrieval/QUALITY.md), [PostgreSQL/pgvector roadmap](../../docs/retrieval/POSTGRES-ROADMAP.md).
